## 实现、依赖与边界

复用 PostgreSQL 队列、AgentHarness、现有通知与 SMTP/Resend，未引入新服务供应商。认领与写入使用数据库事务锁及 token 校验；步骤/工具检查继续验证请求者、租户与成员资格。失去租约的尝试回滚，不能将新尝试改回重试/失败。该保护覆盖现有 SQLAlchemy Session 工作流，不是对任意未来独立连接或外部副作用的通用防护；新工具必须沿用授权与幂等契约。

截止邮件意图和收件人分别持久化。发送前重验有效用户/租户/成员、邮箱与私有通知目标；意图创建时先保存正文快照。不把实际发送与数据库提交称为原子操作：供应商接收后断线或进程崩溃可能无法判断是否已送达，置 uncertain，禁止自动重发。SMTP 数据阶段明确拒绝/HTTP429 可有限重试；认证拒绝失败；网络结果不明需人工核实。每人最多4次，重试间隔60/120/240秒；sending 超时120秒后待核实。没有真实供应商到达率结论。

迁移 `20261023_0028` 只新增 nullable AgentRun.lease_token 和 notification_deliveries；不猜测历史送达、不改旧订单、密码、证据或历史金额。旧 `:emailed` 通知保留去重兼容。新增可选 notification-worker 容器 profile `notifications`，默认不启动；EMAIL_ENABLED 与现有供应商配置仍控制发送。原 Agent worker 小时扫描也使用同一 outbox，两个新版处理进程可通过行锁协作。验证码与现有发票邮件仍同步发送，本批不声称已完成其 outbox。

## 实际失败与修正

新增故障测试初轮7通过3失败：psycopg INSERT rowcount 为-1，影响新增数量统计。改为 RETURNING id 判定插入成功，复验26项通过，再补充传输分类及并发/迟到结果反例。完整集初轮在已有定向测试库运行，215通过3失败：全局组织计数与无过滤队列测试受已有合成记录干扰。保留原库及失败日志，另新建全套专用库，未清库/改账/放宽断言，最终220项全部通过。旧兼容脚本首次解析了虚拟环境符号链接，误用系统Python缺SQLAlchemy；改为保留虚拟环境路径后验证成功。Compose编辑时发现嵌套匹配误插入，已修复并解析结构验证，未部署过该临时内容。
