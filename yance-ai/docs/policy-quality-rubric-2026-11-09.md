# 政策质量评估体系说明（quality-rubric-v1.1）

> 适用对象：客户交付评审、内容运营、后续维护人员
> 落地位置：`/opt/yance/collector-20261107-r5/app/services/policy_collection/quality.py`
> 生效版本：`quality-rubric-v1.1`（2026-11-09）

## 1. 这套体系要解决什么

采集到的政策文件有三种"看起来都对、实际不能用"的情况，客户踩过一次就不会再信任第二批数据：

| 客户的真实问题 | 对应维度 | 不解决会怎样 |
|---|---|---|
| 这份文件真的是科技厅发的吗？会不会是自媒体转的、截断的、拼错的？ | 信度 Reliability | 引用后被客户质疑来源，谈单失败 |
| 它现在还有效吗？是不是已经被废止、过期、被新文件取代了？ | 效度 Validity | 客户拿废止文件去申报，直接误事 |
| 我能拿它做什么？有申报条件、材料、截止日期、额度吗？ | 有效性 Utility | 只是一段新闻通稿，无法转化为行动 |

所以评分不是一个总分，而是三条独立的轴。任何一条轴出致命问题，文件都不进入交付集——哪怕另外两条满分。

## 2. 评分结构

### 2.1 总分权重

| 轴 | 权重 | 为什么是这个权重 |
|---|---|---|
| 信度 Reliability | 40% | 客户第一问永远是"这是原文吗"，可追溯性优先于一切 |
| 效度 Validity | 35% | 现行有效是能不能用的前提 |
| 有效性 Utility | 25% | 决定客户能不能落地执行，但它是加分项而非准入项 |

### 2.2 信度（40%）— 能否证明这是官方原文

| 子信号 | 权重 | 判据 |
|---|---|---|
| 来源权威性 | 35% | 分 A/B/C/D 四级：国家/省级 `.gov.cn` + 有发文机关 = A（100）；市/区级官方页 = B（88）；官方页但缺机关或层级不明 = C（65）；非官方域名（聚合站、商业转载）= D（35） |
| 原文留痕 | 25% | 有本地快照 = 100；只有原始 URL 记录 = 60；两者皆无 = 0（并记 `no_original_snapshot`） |
| 正文完整性 | 18% | ≥3000 字 100；≥1500 字 85；≥800 字 65；≥300 字 40；<300 字 10 且触发硬否决 |
| 元数据完整度 | 12% | 6 项计分：标题、发文机关、发布日期、层级、来源链接、文号（形如〔2026〕3 号） |
| 文本洁净度 | 10% | 导航栏残留、连续空白、乱码、页脚模板占比越低分越高 |

### 2.3 效度（35%）— 是否现行、是否适用于它声称的区域

| 子信号 | 权重 | 判据 |
|---|---|---|
| 有效性状态 | 32% | 标题/正文前 600 字识别废止、失效、停止执行。强信号（标题含"废止"、正文"自本通知印发之日起废止"）= 0 分并硬否决；弱信号（顺带提及其它文件废止）= 50 分并记 `abolish_mention` 待人工确认 |
| 时效窗口 | 28% | 有失效日期且已过期 = 0 分硬否决；尚未生效 = 85 分并标注"不可作为现行依据"；有明确有效期 = 100；无有效期但 3 年内发布 = 92；3–5 年 = 70 并提示确认；超过 5 年 = 45 |
| 区域自洽 | 18% | 层级与行政区划必须匹配：国家级不得绑定具体省份，省级必须落到省，市级必须落到市，区县级必须落到区县。矛盾 = 0 分硬否决（常见于抓到了导航页或摘要页） |
| 版本新旧 | 12% | 该文件在库内是否最新版本；被更新版本取代 = 40 分硬否决 |
| 主题相关度 | 10% | 科技创新/产业扶持术语命中率（科技、研发、创新、专精特新、人才、资金、补助、奖励、税收、知识产权等），命中不足记 `off_topic` |

## 3. 硬否决项（任一命中即不可交付）

分数再高也不能抵消以下问题，命中即 `deliverable = false`，等级强制为 D：

| 代码 | 含义 |
|---|---|
| `policy_abolished` | 文件本身已废止/失效 |
| `policy_expired` | 有效期已过 |
| `region_conflict` | 层级与行政区划自相矛盾 |
| `superseded_version` | 已被同政策的新版本取代 |
| `text_incomplete` | 有效正文不足 300 字 |
| `no_chunks` | 无可检索段落，无法引用 |
| `no_source_url` | 缺少官方来源链接 |

300 字阈值与采集链路原有的结构闸门 `PUBLISH_MIN_CHARS` 完全一致——两处闸门对"什么算一份文件"的判断不允许出现分歧。

## 4. 等级与交付口径

| 综合分 | 等级 | 交付口径 | 说明 |
|---|---|---|---|
| ≥ 85 | A | 可直接交付 | 无需附加说明即可对外引用 |
| 70–85 | B | 附注交付 | 可用，但需随附待关注项（如未标有效期、可执行要素偏少） |
| 55–70 | C | 仅内部参考 | 不作为对外交付物 |
| < 55 或命中否决项 | D | 扣留 | 不进入交付集，保留在库内供追溯 |

判定为废止、过期、层级矛盾等淘汰结果时，系统同时写一条人类可读的结论（如"正文/标题显示该文件已废止或失效"）和结构化待关注项代码，客户或运营可逐条复核，不需要相信一个黑箱分数。

## 5. 规则如何自动生效（不需要人工触发）

评分不是事后跑的一次性报表，而是嵌进采集流水线的发布闸门：

```
抓取 → 结构化解析 → [结构闸门] → [质量闸门 quality-rubric] → 发布 published → 检索/交付
                                    ↓ 命中否决项
                              pending_review（保留原文与原因码）
```

- 采集器每个周期在发布环节调用评估：通过则写入 `policy_quality_assessments` 并回写 `policies.quality_score / quality_grade / quality_deliverable / quality_assessed_at`，随后才允许发布；未通过则退回 `pending_review` 并记录原因码 `rubric_blocker:<代码>`。
- 检索链路同步生效：混合检索与关键词检索默认过滤 `quality_deliverable = false` 的条目，前端需要时可显式放开低质量结果。
- 交付物导出只包含 `deliverable = true` 的记录，保证客户拿到的表格与接口返回的口径一致。

### 运维命令

```bash

# 全量重算并落库（规则改动后执行）

```

解读要点：

- **有效性只有 66.3 分是真实短板**，主要来自"可执行要素偏少"和"无具体额度"——即库内相当比例是通知类的转发文件，而非带申报条件的指南。这是采集源结构问题，不是评分问题，下一步应补充"申报指南/资金管理办法"类信源。
- **76 份扣留件构成合理**：废止通知、废止决定节选、层级矛盾的碎片页、正文不足的摘要页。
- **135 份公告体裁**（核准名单、公示、招聘、中标结果）被扣 15 分效度但未剔除，因为它们对客户仍有信息价值，只是不作为"政策依据"交付。

## 7. 已知局限

1. 全部判据为确定性规则（正则、长度分桶、元数据比对），不使用模型打分——同样的输入永远得到同样的分数，任何结论都可人工复算。代价是对表述变体的覆盖有限，例如以"自发布之日起 5 年"表述的有效期可识别，写成"有效期至 2031 年 12 月 31 日且不再另行通知"则可能漏判。
2. 区域自洽检查依赖采集时写入的 `province / city / district` 字段。字段缺失会被判为"层级与区划不一致"，宁可错扣也不放行（当前因此被扣留的个案可逐条用 `quality-explain` 复核）。
3. 主题相关度按术语命中率计算，对"教育、医疗、农业"等非科创口径的扶持政策会偏低，若客户学科范围扩大需同步维护 `_TOPIC_TERMS`。
4. 规则版本号与历史评分绑定：`quality-rubric-v1.1` 的结果与 v1.0 并存于表中，便于对比规则调整带来的差异；接口与报表始终读取当前版本。
