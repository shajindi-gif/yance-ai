# 衍策商业化联合验收执行指令

在当前衍策仓库执行一次完整的商业化验收。交付可复现的实测结果、客户能使用的范围和阻断发布的问题。持续完成可独立执行的检查。此次任务是验收，可以编写隔离测试、夹具和报告。保留现有工作，发现产品缺陷时先留证，不在本次验收中修改被测行为。

## 版本、环境和证据

- 读取适用的 AGENTS.md、README、部署记录、客户复核契约、audits/product-acceptance/、audits/joint-web-review-20261030/ 和 yance-ai/docs/policy-retrieval-evaluation.md。旧报告只用作回归清单。记录当前提交、脏文件、前后端与数据库版本，区别本地候选、隔离实测和生产实测。
- 用公开可访问的 Harvey、切问学术官方材料核对可观察的专业工作流，记录链接和观察日期。重点观察如何找到依据、从答案跳到原文、处理不确定性及交付工作成果。无法确认的能力留空。“硅谷标准”在本项目中以以下可重复验收的任务和门槛衡量。
- 先检查测试配置。构建、浏览器和集成测试使用隔离 API、测试库、合成或授权脱敏数据。阻断生产写请求、真实扣退款、开票、短信邮件及申报。生产仅做现有授权范围内的只读核查和聚合统计。禁止输出客户资料、凭据、支付流水号。无外部访问时继续本地验收。

## 必须实际走通的任务

1. **首次到访与登录**：桌面和手机从首页找适用对象、可购买交付、价格和下一步。通过邮箱和手机号两个入口，在隔离环境分别验证注册、登录、过期、返回原页面和错误恢复。确认示例标注、图片无悬浮文字、页面承诺与实际能力一致。
2. **企业完成一次申报准备**：从空账户开始，确认企业事实与地域，检索政策，打开资格矩阵，从关键判断定位到对应版本的原文或附件条款，创建项目，补证，起草材料，由客户本人或授权成员复核并导出。更改事实或政策版本后重查复核状态。对每步记录操作人、输入、成功标志、耗时、失败后下一步。用真实页面与本地真实接口走一遍，截图脱敏。
3. **园区协作**：用两个租户和实际支持的角色，分别验证授权前、授权中、撤销后的检索、文件下载、导出和后台任务。园区内企业互不可见。尚未实现园区授权时写明产品边界，不以管理员代替园区客户验收。
4. **使用到收入**：以当前服务端可售产品，从企业选购、报价、下单、支付、权益、固定版本报告、客户下载走完，再单独走客户申请发票、开具状态和授权下载。核对同租户、同订单、同金额币种、同交付版本；付款凭证与正式发票分别验收。覆盖取消、刷新续付、重复和并发回调、跨渠道尝试、乱序、超时、错金额、越权下载、人工开票失败恢复。分别标记合同模拟、渠道沙箱和真实历史对账证据。
5. **生产商业证据**：此前聚合查到4笔报告订单、12次支付记录且状态均为created。只有当期只读复核才能更新该结论。同一订单多次尝试不算收入。没有商户账单时标为渠道结果待对账。分别报告可售、隔离流程通过、渠道确认收款、实际授权交付、申请者取得正式票这五项，不推算收入或成交率。

## 专业质量与可靠性

- **数据供应**：把“全天采集”作为待验假设。取最近24小时和7天的来源健康、游标推进、去重新增、变更版本、失败与积压、原文附件落盘及实际可检索量。至少追一条新采文件从官方来源到普通用户网页命中并打开原文。分列政策、批次、附件、历史版本和分块，注明分母和覆盖空白。
- **答案准确性**：冻结带官方原文和标注依据的题集，覆盖园区归属、错地域、申报窗口、资金上限、缺证、附件条件、新旧冲突、提示注入。分别报告 Recall@K、条款引用支持率、误判符合、漏掉机会及恰当拒答；列出严重错例。尽可能对比同一模型在常规使用、同资料、衍策完整流程下的结果，记录模型版本、预算、题数、标签来源和限制。无付费配置仍执行关键词检索和引用抽检。用合成企业所得结果不作为真实业务准确率。
- **体验与工程**：按项目脚本运行类型检查、lint、构建、关键单元和集成测试、Playwright；具备环境时运行 axe 和 Lighthouse。检查手机长表格、中文长文、焦点、键盘、对比度、加载、空结果、超时、重试、重复提交、未保存恢复。记录浏览器、设备、网络、样本量；实验室指标与真实用户指标分列。输出用户完成任务的步骤数、耗时和实际卡点。自动化操作耗时不充当用户研究。
- **安全运维与成本**：验证租户隔离、对象下载、会话撤销、恶意文档、SSRF、日志脱敏、采集和 Agent 的重试与费用上限、备份恢复与版本回退。只在隔离环境演练故障。按一次成功交付归集可证实的成本；缺少账单、真实使用或访谈时注明证据缺口。

## 判定与交付

按企业自助试用、园区授权试点、公开收费三种场景分别给出 Go／有条件 Go／No-Go。功能正确性、数据与证据、使用体验、商业交付、安全、运维六项分别评分，给出评分依据、证据范围，未测项写“未验证”。跨租户泄露、重复授予付费权益、可收款却无对应可交付报告、关键无依据资格结论均为P0，一项即可阻止受影响场景发布。关键付款或交付链路缺少验证时，不给公开收费无条件Go。

把结果放在 audits/commercial-acceptance-YYYYMMDD/（以实际日期命名）。交付一页验收结论、逐步旅程与失败截图、实际命令和环境、指标与分母、问题清单和复测顺序。每个问题给出优先级、用户影响、环境、URL或文件行号、复现、预期与实际、修复建议和验收条件。最终先回答：今天谁可以用，能完成哪项任务，能否收款并交付，开票如何验收，最大的阻断是什么。不要部署，报告中明确尚需业务方提供的最小外部证据。
