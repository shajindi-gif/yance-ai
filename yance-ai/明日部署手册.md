# yance.ai 明日部署手册

版本：v0.1.0　目标：在一台阿里云 ECS 上运行 Nginx + FastAPI，连接同 VPC 的 RDS PostgreSQL/pgvector 与私有 OSS。

> 先看最重要的限制：若 ECS 位于中国内地且服务通过域名或公网 IP 对外开放，必须先完成 ICP 备案；API 子域名也不例外。没有备案而必须明天公网可访问时，选择阿里云中国香港地域；若必须使用内地地域，则明天只能完成服务器部署和内网/受限验收，待备案后再开放域名。参见[阿里云备案说明](https://help.aliyun.com/zh/dws/icp-filing)。

## 二、阿里云控制台创建资源

### 1. 网络

创建或选择一个 VPC 和交换机。记录 VPC ID、交换机 ID 和网段。后续 ECS 与 RDS 必须选择同一地域、同一 VPC；这样数据库走内网，不申请 RDS 公网地址。

### 2. ECS

建议起步配置：Ubuntu 24.04 LTS、2 vCPU、4 GiB、40–80 GiB ESSD、按量或包年包月、公网 IP。生产试点更稳妥可用 4 vCPU/8 GiB。

安全组入方向只配置：

| 协议/端口 | 来源 | 用途 |
|---|---|---|
| TCP 22 | 你的固定公网 IP `/32` | SSH |
| TCP 80 | `0.0.0.0/0` | HTTP/证书验证 |
| TCP 443 | `0.0.0.0/0` | HTTPS |

不要开放 8000、5432、2375。阿里云也建议 SSH 只授权固定 IP，80/443 才可对公网开放，参见[安全组官方说明](https://help.aliyun.com/zh/ecs/user-guide/start-using-security-groups)。下载并妥善保存 SSH 私钥；遗失后不要通过聊天传输。

### 3. RDS PostgreSQL

创建 PostgreSQL 16（若控制台可选更新兼容版本也可以，但本包以 16 验证），地域/VPC/交换机与 ECS 相同。试点可先用基础/高可用的最小合适规格；生产客户数据建议高可用版并启用自动备份、日志备份和删除保护。

在实例中：

1. “账号管理”创建 `yance_app`。数据库密码建议使用字母、数字、`_`、`-` 组合，既满足复杂度又无需在 URL 中转义。
2. “数据库管理”创建 UTF-8 数据库 `yance_prod`，Owner/授权账号选 `yance_app`。
3. “白名单与安全组”新建 `yance-ecs` 分组，只填 ECS 私网 IP（例如 `172.16.1.10`），绝不填 `0.0.0.0/0`。官方说明见[RDS 白名单](https://help.aliyun.com/zh/rds/apsaradb-rds-for-postgresql/configure-an-ip-address-whitelist-for-an-apsaradb-rds-for-postgresql-instance-1)。
4. 不申请外网连接地址。复制“内网地址”和端口。
5. 在 DMS 中以高权限账号连接 `yance_prod`，执行：

```sql
CREATE EXTENSION IF NOT EXISTS vector;
SELECT extname, extversion FROM pg_extension WHERE extname = 'vector';
```

RDS 官方确认 pgvector 可用于向量类型和相似度检索，参见[RDS RAG 指南](https://help.aliyun.com/zh/rds/apsaradb-rds-for-postgresql/use-rds-for-postgresql-to-create-a-rag-based-application)。若创建失败，进入实例“插件管理”确认当前版本支持并安装，或联系阿里云工单；不要删除迁移里的 vector 字段冒充成功。

### 4. OSS

创建与 ECS 同地域的 Bucket：

- ACL：私有
- 阻止公共访问：开启
- 服务端加密：开启（首版可 SSE-OSS；有 KMS 再升级 SSE-KMS）
- 版本控制：建议开启
- 生命周期：先不要自动删客户原始文件；确定保留规则后再配

在“权限控制 → 跨域设置（CORS）”新增规则，让浏览器可直接 PUT 到预签名 URL：

- 来源：正式前端域名，例如 `https://app.yance.ai`；开发期可另加 `http://localhost:3000`
- 允许方法：PUT、GET、HEAD
- 允许 Headers：`*`
- 暴露 Headers：`ETag`
- 缓存时间：600 秒

不要把来源设为 `*` 并同时携带凭据。API 使用 `OSS_ENDPOINT` 生成公网预签名 URL，使用 `OSS_INTERNAL_ENDPOINT` 从 ECS 检查对象是否存在；两者不能填反。

创建专用 RAM 用户（例如 `yance-oss-app`），开启 OpenAPI AccessKey，不给控制台登录。创建并绑定下列自定义策略，替换 `YOUR_BUCKET`：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "oss:PutObject",
        "oss:GetObject",
        "oss:HeadObject",
        "oss:AbortMultipartUpload",
        "oss:ListParts"
      ],
      "Resource": ["acs:oss:*:*:YOUR_BUCKET/*"]
    }
  ]
}
```

不要授予 `AliyunOSSFullAccess`。OSS 官方建议 Bucket 保持私有并使用 RAM Policy 做最小权限，参见[权限概述](https://help.aliyun.com/zh/oss/user-guide/permissions-and-access-control-overview)和[RAM Policy](https://help.aliyun.com/en/oss/user-guide/ram-policy/)。保存 AccessKey 后关闭页面。

## 三、建立 GitHub 仓库并推送

在 GitHub 新建 Private 仓库 `yance-ai`，不要勾选自动创建 README。把本 ZIP 解压，在本机工程根目录执行：

```bash
git init
git add .
git status
git commit -m "feat: bootstrap yance.ai backend v0.1.0"
git branch -M main
git remote add origin git@github.com:YOUR_ORG/yance-ai.git
git push -u origin main
```

在 `git status` 中确认 `.env`、`.env.production`、`.pem`、`.key` 没有进入暂存区。GitHub 仓库设置中：

1. 为 `main` 建分支保护，要求 PR 和 CI 通过。
2. 建 Environments：`staging`、`production`；production 要人工审批。
3. 建 Project，列设为 Backlog / Ready / In Progress / Review / Testing / Released。
4. 第一次部署建议手工完成；`.github/workflows/deploy-example.yml` 只作样例，确认 SSH 网络与审批策略后再启用。

## 四、登录 ECS 并安装 Docker

本机执行：

```bash
chmod 600 /path/to/your-key.pem
ssh -i /path/to/your-key.pem ubuntu@ECS_PUBLIC_IP
```

在 ECS 上按 Docker 官方 Ubuntu 仓库方式安装：

```bash
sudo apt update
sudo apt install -y ca-certificates curl git
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
sudo tee /etc/apt/sources.list.d/docker.sources >/dev/null <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo usermod -aG docker ubuntu
sudo systemctl enable --now docker
exit
```

重新 SSH 登录后验证：

```bash
docker version
docker compose version
```

安装依据见[Docker Engine Ubuntu 官方文档](https://docs.docker.com/engine/install/ubuntu/)。

## 五、拉代码并配置生产变量

推荐给 ECS 配置只读 GitHub Deploy Key；首次也可使用你的 SSH Agent。然后：

```bash
sudo mkdir -p /opt/yance-ai
sudo chown ubuntu:ubuntu /opt/yance-ai
git clone git@github.com:YOUR_ORG/yance-ai.git /opt/yance-ai
cd /opt/yance-ai
cp .env.production.example .env.production
chmod 600 .env.production
```

生成三个不同的随机密钥，分别用于 JWT、一次性 Bootstrap 和后续租户开通：

```bash
openssl rand -hex 32
openssl rand -hex 32
openssl rand -hex 32
```

编辑：

```bash
nano .env.production
```

必须替换：`CORS_ORIGINS`、`DATABASE_URL`、`JWT_SECRET`、`BOOTSTRAP_TOKEN`、`TENANT_PROVISIONING_TOKEN` 和所有 `OSS_*`。`OSS_ENDPOINT` 是公网地址，`OSS_INTERNAL_ENDPOINT` 是内网地址。`DATABASE_URL` 必须使用 RDS 内网地址，并保留 `?sslmode=require`。模型密钥可全部留空，`LLM_DEFAULT_PROVIDER=mock` 不影响核心 API 上线。租户开通密钥只能保存在可信服务端，绝不能进入浏览器前端。

检查所有占位符已消失：

```bash
grep -n 'REPLACE\|change-' .env.production
```

正确结果应无输出。不要执行 `cat .env.production`，避免秘密进入终端录屏或日志。

## 六、首次启动

先确认 `nginx/conf.d/default.conf` 的 `server_name` 是实际 API 域名。然后：

```bash
cd /opt/yance-ai
git rev-parse HEAD | tee .deployed-commit
docker compose -f docker-compose.prod.yml config --quiet
docker compose -f docker-compose.prod.yml build
docker compose -f docker-compose.prod.yml up -d
docker compose -f docker-compose.prod.yml ps
docker compose -f docker-compose.prod.yml logs --tail=200 migrate api nginx
sh scripts/smoke_test.sh http://localhost
```

成功标准：migrate 以代码 0 结束；api/nginx 为 running/healthy；两个 health 请求通过。若失败先跳到“十、故障定位”，不要重复改数据库。

## 七、DNS 与 HTTPS

### DNS

云解析 DNS → 目标域名 → 解析设置 → 添加记录：

- 类型：A
- 主机记录：`api`
- 记录值：ECS 公网 IPv4
- TTL：默认/10 分钟

官方步骤见[添加解析记录](https://help.aliyun.com/zh/dns/pubz-add-parsing-record)。验证：

```bash
dig +short api.yance.ai
curl http://api.yance.ai/health
```

### HTTPS（Certbot Webroot）

DNS 已生效且 80 端口可访问后，在 ECS 执行：

```bash
sudo mkdir -p /etc/letsencrypt /var/www/certbot
docker run --rm \
  -v /etc/letsencrypt:/etc/letsencrypt \
  -v /var/www/certbot:/var/www/certbot \
  certbot/certbot certonly --webroot -w /var/www/certbot \
  -d api.yance.ai --email YOUR_EMAIL --agree-tos --no-eff-email
cp nginx/https.conf.example nginx/conf.d/default.conf
docker compose -f docker-compose.prod.yml restart nginx
curl https://api.yance.ai/health
```

若不是 `api.yance.ai`，必须同时替换 HTTPS 配置中的域名和证书路径。证书续期可先每月人工执行并验证；正式运营前配置定时 `certbot renew` 和 Nginx reload，或改用阿里云证书自动部署。阿里云证书方案见[SSL 部署说明](https://help.aliyun.com/zh/ssl-certificate/ssl-certificate-deployment-scheme-selection)。

## 八、创建第一个租户与 Owner

只执行一次。先在本地密码管理器准备真实 Owner 邮箱和至少 12 位密码。在 ECS 中读取 bootstrap token 并调用本机接口（避免经公网传 token）：

```bash
cd /opt/yance-ai
set -a
. ./.env.production
set +a
curl --fail -X POST http://localhost/api/v1/auth/bootstrap \
  -H 'Content-Type: application/json' \
  -H "X-Bootstrap-Token: ${BOOTSTRAP_TOKEN}" \
  -d '{"tenant_name":"Yance AI","tenant_slug":"yance-ai","owner_email":"OWNER_EMAIL","owner_name":"Yance Owner","owner_password":"STRONG_OWNER_PASSWORD"}'
unset BOOTSTRAP_TOKEN TENANT_PROVISIONING_TOKEN DATABASE_URL OSS_ACCESS_KEY_ID OSS_ACCESS_KEY_SECRET JWT_SECRET
```

保存返回 token 仅用于首次验收，随后通过登录接口获取新 token。接口若返回 409 表示已经初始化，属于正常保护，不要删库重试。

## 十、故障定位

### API 起不来

```bash
docker compose -f docker-compose.prod.yml ps
docker compose -f docker-compose.prod.yml logs --tail=200 api migrate
```

- `Production secrets must be replaced`：`.env.production` 仍有默认密钥。
- `connection refused/timeout`：检查 RDS 内网地址、同 VPC、白名单 ECS 私网 IP。
- `password authentication failed`：账号、密码或 URL 不正确；含特殊字符时需 URL 编码。
- `extension vector is not available`：先用 DMS 高权限账号安装 pgvector。

### OSS 403

检查公网/内网 Endpoint 是否同地域且未填反、Bucket 拼写、RAM Policy 的 Resource、AccessKey 是否启用、Bucket CORS 和服务器时间。Bucket 继续保持私有，不要通过改成公共读写“解决”。浏览器无法解析 `-internal` 域名通常表示预签名错误使用了内网 Endpoint。

### 外网访问失败

先 `curl http://localhost/health`。本机成功而公网失败时检查 ECS 安全组 80/443、DNS A 记录和备案状态；不要开放 8000 绕过 Nginx。

### HTTPS 失败

确认 DNS 已指向当前 ECS、80 可访问、证书目录存在、配置域名与证书路径一致：

```bash
docker compose -f docker-compose.prod.yml exec nginx nginx -t
docker compose -f docker-compose.prod.yml logs --tail=100 nginx
```

## 十一、安全回滚

发布前必须记录旧 commit 并创建 RDS 手动快照。应用回滚：

```bash
cd /opt/yance-ai
git log --oneline -10
git checkout --detach PREVIOUS_GOOD_COMMIT
docker compose -f docker-compose.prod.yml up -d --build
sh scripts/smoke_test.sh http://localhost
```

不要在生产直接执行 `alembic downgrade`；迁移可能已写入不可逆数据。若新迁移导致数据问题，停止写入，用发布前 RDS 快照恢复到新实例，验证后切换 `DATABASE_URL`。恢复前保留故障实例供取证。
