在本机衍策仓库实际检修并改进现有前端，交付本地可浏览的候选版。先读适用的 AGENTS.md、README、最近发布记录及前端验收，检查 Git 状态并保留用户工作。本轮只授权本地修改与隔离验证。

先用浏览器复现用户觉得“像几个旧版本拼在一起”的具体位置。用当前源码启动前后端，显式指定本机 API 与隔离库，拦截外部业务请求。在首页、政策发现、项目详情、移动导航、登录、定价和订单各走一遍。记录哪个任务中出现了两次同义解释、重复入口、视觉冲突或错误状态。对视觉问题在开发者工具中查看实际生效的样式及来源。检查同一 URL 在新会话和普通刷新后的表现，区分当前页面内容、样式覆盖和缓存。从旧版保留的静态资源用于兼容旧标签页，只有在新页面确实加载了错误资源时才按缓存故障处理。

优先完成以下三批实际修改，每批先保存改前截图或可重复的操作，再验证修复。
1. 首页面向第一次来访的企业申报人员。检查 industry-scenes、for-business、scenarios、start-with-your-task 的内容和链接，对照首屏与下方是否重复使用同一张图、同一句承诺或同一个入口。合并没有独立任务的段落，保留旧锚点和有效深链。让用户在首屏知道能做什么，在下一屏看到政策条件、企业事实、证据缺口和原文如何对应。优先复用已实现的产品组件或经脱敏的真实界面，合成示例明确标注。保留用户提供的行业图，按行业内容选位置，图片上不放悬浮文字、按钮或标签。
2. 统一官网与工作台。追踪根布局同时引入的 globals.css、design-system.css，以及 CSS Modules 和页面内样式。针对已复现的冲突，归并到负责该组件的样式源，验证所有调用方之后再移除旧规则。检查桌面与手机导航、按钮、表单、状态、表格和弹层。沿用品牌蓝、暖白底、系统中文字体；文档主区、选中条款、来源详情形成清晰层次。项目里点开依据时保留当前任务，手机关闭详情后回到原条目。优先减少用户从“发现缺口”到“补证”需要的操作。
3. 修复可复现的功能缺陷。按实际入口验证统一邮箱/手机号登录与回跳、检索与原文高亮、项目复核与授权导出、报价与订单恢复。覆盖慢请求、报错重试、无结果、无权限、重复点击、手机返回和未保存输入。保留服务端权限、报价、权益及发票语义。优先修复阻断任务、丢失输入或误报成功的问题。操作使用隔离数据，支付仅用已有隔离合同或沙箱。若发现必须修改后端的缺陷，给出最小复现和影响范围，继续处理独立前端问题。

验收以用户实际能做的事为准。在 390、768、1440 像素宽度复走核心路径，检查键盘焦点、页面溢出、长中文、图片裁切和错误恢复。改前改后用同一构建模式、数据、视口与滚动位置截图；记录首页哪些重复内容已合并、保留的入口在哪里、完成同一任务的操作步数是否变化。执行现有 lint、typecheck、单元测试、生产构建和相关 Playwright 测试。需要更新旧文案断言时保留对用户行为和结果的验证，报告真实接口与模拟测试各自覆盖的范围。

完成后提供本地预览链接、代表性前后截图、逐项缺陷及验证结果、遗留问题和候选提交。普通可逆设计选择自行处理，持续执行到可验收交付。生产发布在候选版审阅后另行确认。
