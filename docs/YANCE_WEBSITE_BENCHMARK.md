# 全球 AI SaaS 官网对标（Phase 1）

核验日期：2026-11-18。只记录本次实际打开的页面。未打开的站点标为未验证，不根据记忆补设计模式，也不复制文案、商标或视觉资产。

借鉴边界：信息层级、证据呈现、行业入口和转化路径。Yance 保持青色、纸色与中文证据工作台语气，不拼贴各家品牌。

## 已核验首页

### 1. glean.com

1. 首屏一句话定义“企业级上下文”，主 CTA 是预约演示，而不是先堆功能清单。
2. 安全与权限单独成块，并列出可核验的合规框架名称。
3. 行业页按金融服务、医疗、科技等切换同一产品能力，而不是每行业换一套产品。
4. 客户故事带职务与具体用法；没有授权就不该仿造这类引言。
5. 平台叙事是“连接知识 → 理解上下文 → 采取行动”，适合改写成 Yance 的资料、政策、依据、行动。

### 2. hebbia.com

1. 定位句把产品限制在金融严谨性，而不是泛 AI。
2. 首屏用矩阵界面表达“大量材料、逐列判断”，和资格矩阵同构。
3. 强调团队协作，而不是单人聊天。
4. 页面服务机构买方，适合投资机构入口，但 Yance 不能宣称已有组合级矩阵。

### 3. harvey.ai

1. 买方分“律所 / 法务内部团队”两列，Yance 可对应“科技企业 / 园区与投资机构”。
2. 产品模块用短名称（Agents、Vault、Research），每个都说明工作结果。
3. 数字只出现在对方自己公布的采用规模旁；Yance 没有同类已公布数字，故不展示。
4. 安全控制写成采购清单：SSO、审计、数据生命周期。Yance 只链接现有 `/security`，不新编认证。

### 4. rogo.ai（本次打开的是 rogo.ai，不是 rogo.com）

1. 首屏直接写“为金融而建”，垂直定位优先于模型能力。
2. 用工作流步骤（读材料、更新项目、刷新比较）代替抽象“AI 赋能”。
3. 引言来自具名机构；Yance 继续保持“暂无授权案例”。
4. 信任句是部署与权限，不是准确率口号。

### 5. alpha-sense.com

1. 价值主张是“可信任的研究”，并强调句级引用、可追溯假设。
2. 内容规模（文档数量）是他们的公开卖点。Yance 的知识库页已声明数量待统计，因此不模仿这个数字模块。
3. 工作流覆盖从信号到交付物，中间不丢依据。
4. 客户故事按用途分类：竞争情报、尽调、研究提速。

### 6. fiscalnote.com

1. 政策产品的首句是“政策情报的事实来源”，并立刻说明问题不是信息不够，而是分不清哪条与本机构有关。
2. 覆盖表述附带范围（地方到联邦、国家数量）。Yance 只重复自己已有的层级字段，不写未统计的覆盖数。
3. 产品拆成监测、分析、倡导等可购买模块，对应 Yance 已有的检索、核对、材料、按次购买。
4. 用户引言描述节省的研究时间，同样必须有授权才可展示。

### 7. govdash.com

1. 按政府合同生命周期分模块：发现、捕获、定价、标书、履约。
2. 提供两周试点说明，转化预期具体。Yance 的对应动作是免费初筛加按次购买，不新造试点承诺。
3. 安全问答直接回答“是否用客户数据训练”。Yance 安全页已有边界，首页只链过去。
4. 每个模块都有“打开了解”而不是死按钮。

### 8. clay.com

1. 双 CTA：免费试用与预约演示并列。
2. 用“你想做什么”的任务句，而不是功能名。Yance 首页已有“今天想先解决哪件事”，应保留。
3. 结果数字来自具名客户。没有授权时，Yance 用场景示例并标明虚构边界。
4. 数据来源市场被单独说明。Yance 对应表述是“服务器采集的政策 + 客户提供的企业事实”。

### 9. linear.app

1. 界面本身就是首屏，密度高但层级清楚：状态、负责人、活动。
2. 标题短，副标题一句说明为谁、解决什么。
3. 功能按工作阶段分节，每节一个真实界面，不使用装饰性大插画。
4. 主 CTA“开始使用”和“联系销售”分开。

### 10. vanta.com

1. 首屏用买方已经认识的框架名（SOC 2、ISO 等）建立相关性。Yance 可用高企、专精特新等“核对主题”，并声明标签不等于认定。
2. 按公司阶段（初创、中型、企业）分入口。
3. 第三方评测只引用真实报告。Yance 没有对应奖项，不写。
4. 信任引言与产品模块分开，避免功能区看起来像广告墙。

### 11. vercel.com

1. 技术品牌用大量留白、短句和真实产品表面，而不是渐变背景。
2. 最近交付的能力单独成列，便于区分已上线与路线图。
3. 主路径是立即部署，企业路径是联系销售。
4. 页面把“做不到的事”留出反馈通道，而不是藏起来。

### 12. linear.app 与 glean / harvey 的共同转化结构

访客先看懂对象和结果，再看到真实界面，然后按角色进入，最后才是注册或约谈。安全与引用放在转化前，而不是页脚才出现。

## 转成 Yance 设计原则

1. 一句中文价值主张，加一句能力边界。
2. 首屏使用已有产品截图，并保留“合成数据”说明。
3. 能力分成已上线、不能自动认定、未来需求。
4. 行业页共用同一工作流，只改行业问题，不改匹配逻辑。
5. 不展示未统计的政策数量、成功率和客户引言。
6. 注册、查看价格、邮件约演示三条路径都指向已存在的页面或邮箱。
