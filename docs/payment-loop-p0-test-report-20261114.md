# 支付闭环 P0 修复与验收

本轮从 `5f5cdff` 创建 `fix/payment-loop-p0`，保留既有品牌、界面结构、价格、租户权限、历史订单及政策采集。固定业务候选见发布记录；在 `36fa11c` 后继续修复 DNS/压缩库漏洞及真实支付宝请求的编码问题。生产结果单独见发布记录，不以本报告推定已经上线。

## 修复映射

| 问题 | 实现与验证 |
| --- | --- |
| 支付宝回跳不带订单 UUID | `/orders/by-no/{order_no}` 同时识别网站编号和已保存的渠道尝试编号；跨租户 404，未登录 401。成功页保留登录回跳参数，不相信 URL 的成功标记。 |
| 回调丢失后一直待付款 | 新增支付宝主动查单，验签后校验订单、商户和金额，统一经过原 `settle_payment`。旧版同步返回接口补登录、租户及应用校验。支付宝回调返回明确纯文本 `success`。 |
| 过期链接和二维码 | 新订单由服务端决定期限；微信下单设置期限，过期二维码隐藏。只有查询及关单得到确认，才能换新支付尝试编号；未知结果不生成第二个可付款链接。旧订单不回填期限。历史支付宝尝试亦须渠道确认关闭再续付。 |
| 退款缺口 | 平台管理员全额退款接口、持久退款编号、稳定重试、微信验签退款回调。确认后撤销权益并保留审计；开票后的退款进入后续处理事件，不伪造红冲。 |
| 缺少对账 | 按渠道、账期记录运行与差异；签名/账单哈希校验、受限下载、严格 CSV、重复差异幂等。未出账、无权限、验签失败都不能显示一致。共享支付宝应用的其他流水标为未归属。 |
| 结账恢复与死链 | `/policy-scan` 错误入口改为真实 `/discover`；二维码展示服务端期限；支付返回、刷新与重复点击沿用原订单。 |
| 定价抓取与业务表述 | 服务端渲染真实目录，后台目录仍可刷新和重试；只展示已接通的按次报告购买，其他服务折叠为咨询；价格未改，历史价格未回写。 |
| 基础安全与兼容性 | HSTS、微信签名时效、无效异步页面请求取消；补回页面分享图片；修正定价深色区文字对比度。 |

独立英文提交对应以上各项。另修复仓库本来存在的 lint、模型注册/迁移元数据漂移和过时浏览器测试，保留已有数据库结构，无清库或重置密码。

## 生产与外部限制

- 指定对账邮箱尚未注册，未创建或提权任何账号。对账记录可运行，邮件告警保持未绑定/不发送。
- 支付宝继续现有共享应用，按用户明确选择执行。只读渠道账单核验仍有未完成项，详见发布记录；没有可验证账单时不会声称对账一致。
- 没有真实付款、退款到账、正式开票或发票红冲验收；不修改现有 ¥99 商品为 ¥0.01，不伪造回调，不给旧订单补 paid 状态。
- 对公转账仍未开放，其他产品尚无独立验收交付能力，均未擅自启用。
- 此次不改政策采集守护服务。镜像保留生产实际使用的 scheduler，并比对候选/生产文件哈希一致。

## 后续实际阻断与修复

`36fa11c` 的完整 CI 在业务/浏览器通过后，发现 dnspython 2.9.0 和系统 zlib 的可修复高危记录，没有忽略这些告警。DNS 已升级至 2.9.2，官方 PyPI wheel 哈希在同目录 `dependency-manifest.json` 固化，本地 `pip-audit --local --skip-editable` 返回无已知漏洞。升级后身份与支付定向回归 **23/23** 通过。Docker 构建显式安装安全仓库中的 zlib1g，候选镜像同步修复，最终 Trivy 结果见发布记录。

真实只读支付宝账单核验一度验签失败。进一步检查发现未声明 HTTP UTF-8 时渠道返回 GBK；按请求正文正确声明 UTF-8 后，返回 UTF-8，使用原有支付宝公钥验签通过。没有轮换或修改公钥，也未需要用户提供新密钥。增加中文签名响应回归后，相关查单、对账和退款测试 **9/9** 通过。支付宝返回 `NO_BILL_DATA`，微信返回 `NO_STATEMENT_EXIST`，只表示指定账期没有可下载账单，不是已完成交易的对账成功证据。

官方包来源：[dnspython 2.9.2](https://pypi.org/project/dnspython/2.9.2/)；编码处理参照[支付宝官方 SDK](https://github.com/alipay/alipay-sdk-python-all)。只采用协议处理方式，不复制应用或品牌内容。

最终 CI：[43589593659](https://github.com/shajindi-gif/yance-ai/actions/runs/43589593659)。此前的失败运行保留，没有删除记录或降低覆盖率/漏洞门槛。发布前另扫描实际运行基底叠加后的镜像，不能用 CI 的新建镜像扫描代替。
