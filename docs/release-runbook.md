## 回退条件和恢复方式

- **应用回退**：切回已验收且包含本轮关键修复的固定构建；新增数据库列保留。若只有未修复旧版本可用，关闭高风险服务并向用户说明；认证恢复需安全负责人决定受控JWT秘密轮换/全会话失效，不能悄悄回退后让旧token继续有效。轮换必须经用户审批，不能使用本轮测试秘密。
- **数据前向修复**：保留原记录、生成独立修复事件/版本和操作审计；不更改历史交易金额，不把旧deadline当政策expiry_date批量覆盖。待来源确认后发布新的政策版本。
- **订单对账**：拒绝的晚到款与历史多支付意图进入授权人员对账队列；用供应商查询/账单核实金额、商户、交易号，确定退款或补权益方案后另行获得授权。拒绝回调不等于供应商已退款。
- **任务恢复**：暂停领取后核查run、step、tool、artifact和租约状态；先检查是否已经交付/扣额，再恢复幂等任务；取消任务不重新排队。供应商在途请求可能已计费，不能将取消标为零费用。
- **数据库恢复**：仅当数据库负责人确认前向修复不可行、备份可恢复且用户批准数据损失窗口时操作；恢复到新实例并核对，再受控切换。绝不直接覆盖现有生产库来“回滚应用”。
