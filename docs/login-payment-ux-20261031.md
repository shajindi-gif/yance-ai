# 登录与付款体验收敛 · 2026-10-31

本轮仅本地候选，生产及真实交易未变更。基线ec26581。保持企业政策与资源证据工作台定位，沿用邮箱、腾讯云短信、支付宝与微信现有接口，不替换认证或支付供应商。

## 改动

- 登录页面仅保留邮箱、手机两个主入口，不再叠放“登录/免费注册”及“密码/验证码”两组标签。邮箱验证码通道可用时作为默认，首次验证后才补充企业与联系人并同意条款。邮箱密码及密码注册作为邮箱内的次级兼容入口，已有账号和找回密码能力保留。
- 登录能力读取时有等待提示；读取失败可继续用已有邮箱密码。短信未配置时明确不可用，不给虚假入口。登录、发送验证码增加同步防重复请求保护；验证码支持自动填入。
- 手机首次验证成功补资料改为正常引导，不再用红色错误提示。已有邮箱与独立手机号不会擅自合并，仍通过登录后绑定关联。
- 微信付款查询不重叠；收起/离开后忽略迟到的查询响应。只有接口订单status=paid才进入确认页，供应商trade_state单独为SUCCESS不视为已授予权益。
- 查询失败显式提示重试及避免重复付款；十分钟是本页自动查询窗口，不宣称等同供应商二维码有效期。二维码收起保留订单；创建订单后锁定企业及支付渠道，避免订单内容与付款目标变化。渠道尚未支持切换恢复时不诱导重复创建订单。
- 支付返回页读取当前账号的服务端订单，区分未确认、已支付、取消、退款。已确认才显示获取报告和申请开票入口；URL参数不能宣称支付完成，失败支持刷新。
- 手机优先支付宝；微信当前仅Native扫码，明确需要另一台设备。不伪装已接通微信H5或App唤起。

## 实际验证

ESLint、TypeScript、正式构建（含standalone打包）通过。四项Chromium浏览器测试通过：双入口与旧邮箱密码兼容、手机宽度无横溢、返回URL不能伪造已付款且可刷新、渠道失败重试保留同一订单；另覆盖首页现有素材和行动入口。

本轮浏览器使用明确标记的本机合同模拟，拦截外部请求；没有真实短信、邮件、支付或客户测试。不能把这四项当作生产送达或支付沙箱验收。原始日志见audit-evidence/login-payment-ux-20261031。首轮构建因重复disabled属性失败并已修复；首次浏览器运行因该构建没有启动而失败，修复后重跑四项全部通过，不放宽断言。

## 后续验收与回退

尚需真实供应商沙箱、手机原生支付环境与用户试用验证。页面刷新/跨设备的未付订单继续付款、自动对账异常恢复仍需增强；本轮未冒充完成这些能力，也未宣称达到支付宝性能或交易保障。
