# 安全与事故运行手册

## 数据分级

- S0：公开政策文本
- S1：内部产品数据
- S2：企业申报材料、联系人和经营数据
- S3：密码、AccessKey、支付密钥、数据库凭据

S2 只进入私有 OSS/RDS；S3 只进入生产密钥存储或服务器权限为 600 的 `.env.production`，禁止进入日志、Issue、聊天和 Git。

## 首日基线

1. SSH 仅允许管理员固定 IP，禁用密码登录，优先 ED25519 密钥。
2. 只公开 80/443；8000/5432 不对公网开放。
3. RDS 白名单只含 ECS 私网 IP；不申请 RDS 公网地址。
4. OSS 私有、阻止公共访问、RAM 最小权限、开启服务端加密。
5. GitHub main 分支保护，生产 Environment 需要人工审批。
6. RDS 自动备份和日志备份开启；每次迁移前创建手动快照。

## 告警建议

- `/health/ready` 连续 3 次失败
- 5xx 比例 5 分钟超过 2%
- P95 延迟超过 2 秒
- RDS CPU/连接数/存储超过 70%/70%/80%
- ECS 磁盘超过 75%
- OSS 异常下载量、AccessDenied 激增
- 登录失败或跨租户访问拒绝激增

## 事故响应

1. 记录开始时间、版本、影响租户和请求 ID。
2. 停止继续发布；不要删除容器和日志。
3. 泄密时立即禁用/轮换相关密钥，随后排查访问日志。
4. 应用故障按部署手册回滚代码；数据故障先隔离写入，再从 RDS 快照恢复到新实例验证。
5. 结束后 48 小时内写复盘：时间线、根因、影响、恢复、长期动作。
