## 实测

环境：本机macOS，Node26.8.1、npm11.19.0、Next16.4.3、Playwright1.63.0 Chromium。桌面默认Desktop Chrome，手机390×844；未模拟网络限速，不以耗时声称性能提升。

命令（从website运行）：

```sh
npm run typecheck
API_PROXY_TARGET=http://127.0.0.1:9 NEXT_PUBLIC_API_URL=/api/v1 npm run build
API_PROXY_TARGET=http://127.0.0.1:9 NEXT_PUBLIC_API_URL=/api/v1 npm run start -- --hostname 127.0.0.1 --port 3025
PLAYWRIGHT_BASE_URL=http://127.0.0.1:3025 PLAYWRIGHT_EXTERNAL_SERVER=1 npx playwright test e2e/pricing-system.spec.ts
```

最终：类型检查通过；41个路由构建通过；4项浏览器合同测试通过，3.1秒。这是总测试执行时间，不是业务延迟指标。git diff --check通过。

1. 合成目录四档价格与交付状态、报告入口、匿名登录跳转。
2. 修改合成服务端金额和促销价后正确显示；503没有静态报价替代；重试后空目录保持空态。
3. 手机无页面横向溢出，FAQ可用键盘打开，客户复核说明可读。
4. 合成登录/企业资料下结算保留服务器商品身份和金额；移除划线原价；待开通商品不可从该页创建订单；测试期间API写入计数0。

初轮3通过/1失败，原因是测试错误定位“立即支付”（现有按钮为“确认支付”）；随后为未开放商品明确按钮文案“待开通”，相应断言复跑全4项通过。实现时曾有路径和闭合语法错误，已纠正并以最终构建/测试为准。

所有API使用显式标识的合成合同响应，测试仅允许localhost/127.0.0.1，请求其余API返回隔离503，外部域名阻断；Next转发指向本机未监听9端口。没有支付、开票、邮件或生产API调用。Next start对standalone模式提示建议用standalone/server.js，本次实际运行服务完成测试；不把该命令当新的生产启动规范。
