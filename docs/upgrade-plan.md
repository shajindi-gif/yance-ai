## 顺序与发布闸门

先复现反例与保护测试库，再按 P0 小批修复；随后运行现有核心流程并补真实缺口。关键依赖缺失时推进不依赖供应商的合同测试、数据验证和恢复演练。P2 不以“企业级”名义提前上线空壳集成。

发布阻断：跨租户泄漏、重复付费权益、关键无依据资格结论任一失败，或兼容/恢复未验收，均 NO-GO。未执行的测试单列，不能折算为通过。具体执行结果与尚未完成范围见 test-report.md 和 audit.md。
